Rekarina 1.2.4

20 November 2026 · the newest
Release notes

Rekarina 1.2.4: your reports, fixed

A big thank you to everyone who reported problems after 1.2.1: nearly every line below is yours. Open the launcher and it offers the update.

Shaders and stutter

  • Every setup prepares all the shaders again before you play, and an update keeps the ones you already have. 1.2.3 cut them down to the most used ones; your next setup run fills the rest back in (thanks huchi001).
  • No more freezes of a few seconds while playing: the pipeline cache is saved when the game closes instead of every 20 seconds (thanks Ranma_kun, huchi001).

Frame generation

  • FSR frame generation no longer stops the game from starting (thanks matthieugo).
  • DLSS Frame Generation is offered on RTX 40 and 50 cards again. A file of ours was missing from every release since 1.2.0 (thanks matthieugo, lifehawk).
  • If frame generation ever fails to start, the game starts without it and says so.

Controls

  • The dash on the left stick's press and the V key work now: they held the wrong button (thanks Valentyn_L, user7622421).
  • The mouse turns the camera the same everywhere: in houses, in water and while targeting it was slower or capped (thanks 호두의봄).
  • The ocarina no longer freezes the game when the mic input option is on (thanks 창엽, The Mystic's Shade, Valentyn_L).
  • The Controls tab now says what each button does in this game; it showed the wrong descriptions before.
  • The Rekarina menu remembers where you were, so you can close it, look, and keep tweaking (thanks Alejandro Sanz II).

Launcher and setup

  • A "Rekarina Launcher" shortcut in the game folder and in the Start menu, and one on the desktop if you want it (thanks Sir Flarigand).
  • "Open folder" opens the folder instead of starting a second launcher (thanks matthieugo).
  • The setup step "Drawing the button prompts" tries again by itself when it crashes, and says more if it keeps failing (thanks InkJelly80).
  • The setup form highlights whole rows.

New

  • Polish as a game language (thanks remson).
  • Weaker CPUs: with four threads the game's threads share the cores better and the frame is handed to the GPU on two threads. On my CPU held to four threads at 1080p: the field 51 → 59 fps (1% low 19 → 35), the village 52 → 56 fps, and far fewer long frames.
  • The game starts faster: a background read of 177,000 small files at every start is gone.

Still open, I'm on it

  • Crashes in the Market and around the castle on some PCs (thanks huchi001, mekka for the logs). I couldn't reproduce them here yet; the next crash log carries what I need.
  • Depth of field looks pixelated; bosses above 60 fps still need checking; flicker of distant shadows and trees; memory on 16 GB PCs.
  • Linux and Steam Deck: there's a #linux channel now, come help.

Something broken? Esc, Advanced, Make a problem report, and post the zip in #bug-reports.

Rekarina 1.2.3

19 November 2026
Release notes

Rekarina 1.2.3: no more hour-long shader step

  • If you downloaded Rekarina again instead of updating in the launcher, the setup prepared every shader before you could play. That took an hour or more on some PCs, and the timer sat at "2 mins" the whole time. Now it prepares only the shaders the game is known to use, and the launcher does the rest in the background while the game is closed.
  • The timer follows the real progress now.
  • 1.2.2 fixed the update from 1.2.1, which stopped at once with "The setup stopped unexpectedly (exit code 1)".

The easiest way to get it: open the launcher, it offers the update. Everything new since 1.2.0 is below.

Install anywhere, and much faster

  • At its first start Rekarina.exe asks where to put everything: the launcher, its build files and the game go into the folder you pick. C: is not needed any more.
  • A first install takes about 25-35 minutes instead of 85 on my PC. It prepares the shaders the game is known to use; the launcher prepares the rarer ones in the background while the game is closed.
  • An update no longer prepares every shader again, and the prepared shaders take about 5 GB less on your disk.

Frame generation that works

  • Turn it on from the default mode and it switches on what it needs by itself (applies at the next start).
  • RTX 40 and 50 get DLSS Frame Generation; every other card (RTX 20 and 30, GTX, AMD, Intel) gets AMD FSR 3.1 frame generation.

Weaker PCs

  • On a CPU with fewer than six threads the game's own threads no longer fight for it. With my CPU held to four threads at 1080p the 1% low in the open field doubled (22 to 44 fps). Not a steady 60 on four threads yet.

New

  • Dash on its own input: the left stick's press while you move, or a key (V by default). Off by default, in Controls.
  • The song screen shows your controller's buttons (or your keys).
  • The action hint shows its buttons where your Xbox or PlayStation pad has them.
  • Render scale in steps of 5% (50 to 100) in the default mode.
  • The controller's Guide / PS button opens the Rekarina menu.

Fixed

  • The game froze after closing the ocarina's "audio input" notice with voice playing on.
  • The setup stopped at its first step when your Windows user name has a space in it.
  • A "Fatal Error: alloc: invalid block" box when starting the game from the launcher.
  • Above 60 fps: the first dungeon's boss circling the ceiling, the day passing too slowly, the sound job (music, song notes), the horse's fence jumps, moving floors, recording a song, twitching looped poses, cloth, the rigid web. Each fix only acts above 60 fps.

Still open, I'm on it

  • Flickering shadows and trees in the distance, the light inside the great tree, a shadow at the castle.
  • Memory: too much RAM on 16 GB PCs (15+ GB). Being worked on now.
  • A glitchy sound right after playing the ocarina: not reproduced yet. A problem report right after it happens would help a lot.
  • DLSS ghosting on the hero's tunic and hat.
  • The action hint's big button can keep the keyboard's key after you switch a pad on, until the next start.
  • Sharpness for every upscaler, HDR live preview, PsychoV35: coming. Linux and Steam Deck: not ready yet.

Something broken? Esc, Advanced, Make a problem report, and post the zip in #bug-reports.

Rekarina 1.2.1: a day of your reports

Thanks to everyone who played 1.2.0 and wrote in the Discord and on Reddit: almost everything below came from you. Already playing? Open the launcher: it offers the update, and the game is not built from scratch again.

Install anywhere, and much faster

  • At its first start Rekarina.exe asks where to put everything: the launcher, its build files and the game go into the folder you pick. C: is not needed any more.
  • A first install takes about 25-35 minutes instead of 85 on my PC. It prepares the shaders the game is known to use; the launcher prepares the rarer ones in the background while the game is closed. You can play right away.
  • An update no longer prepares every shader again.
  • The prepared shaders are stored compressed: about 5 GB less on your disk.

Frame generation that works

  • Turn it on from the default mode and it switches on what it needs by itself (applies at the next start).
  • RTX 40 and 50 cards get DLSS Frame Generation; every other card (RTX 20 and 30, GTX, AMD, Intel) gets AMD FSR 3.1 frame generation. The row only offers what your card can run and says why.

Weaker PCs

  • On a CPU with fewer than six threads the game's own threads no longer fight for it. With my CPU held to four threads at 1080p the 1% low in the open field doubled (22 to 44 fps) and the long hitches went away. Not a steady 60 on four threads yet.

New

  • Dash on its own input: the left stick's press while you move, or a key (V by default). Off by default, in Controls.
  • The song screen shows your controller's buttons (or your keys).
  • The action hint shows its buttons where your Xbox or PlayStation pad has them: A or cross at the bottom.
  • Render scale in steps of 5% (50 to 100) in the default mode.
  • The controller's Guide / PS button opens the Rekarina menu (Controls tab; the Xbox Game Bar may take it first).

Fixed

  • The game froze after closing the ocarina's "audio input" notice with voice playing on. The option now does nothing (no microphone support yet).
  • The setup stopped at its first step when your Windows user name has a space in it.
  • A "Fatal Error: alloc: invalid block" box when starting the game from the launcher.
  • Above 60 fps: the first dungeon's boss circling the ceiling, the day passing too slowly, the sound job running once a frame (music, battle music, song notes), the horse's fence jumps, moving floors such as a dungeon's barge, recording a song, twitching looped poses, cloth, the web that stayed rigid. Each fix only acts above 60 fps.
  • When a prompt set falls back to the Switch's look, the log says why.

Still open, I'm on it

  • Flickering shadows and trees in the distance, the light inside the great tree, a shadow at the castle. I have your clips, thank you.
  • Memory: too much RAM on 16 GB PCs (15+ GB). Next on my list.
  • A glitchy sound right after playing the ocarina: not reproduced yet. A problem report right after it happens would help a lot.
  • DLSS ghosting on the hero's tunic and hat (the default mode doesn't have it).
  • The big button of the action hint can keep the keyboard's key after you switch a pad on, until the next start.
  • Sharpness for every upscaler, HDR live preview, PsychoV35: coming.
  • Linux and Steam Deck: not ready yet.

Rekarina 1.2.0

19 November 2026
Release notes

Rekarina 1.2.0

New

  • Shaders are ready before play: Rekarina builds every shader and pipeline it knows of before play starts, so the game does not stop to build them while you play. The setup does this once (about a quarter of an hour more in its last step on a 16-thread processor); after that a start takes a few seconds. After a graphics driver update the game rebuilds them at its next start and shows "Preparing shaders..." with a count and the time left: about six minutes on a 16-thread processor, longer on fewer cores, once. You can close the window during it; the next start goes on from there (prep_screen = 0 in rekarina.ini hides the picture, the preparation still runs).
  • The prepared shaders are kept in one file instead of about 250,000 small ones: starts are faster, and an update of an earlier install folds its old shader files into it once.
  • Settings menu: number settings are sliders you drag with the mouse or step with the keys and the pad (mouse speed, dead zones, sharpness, colour, HDR, rumble); the default is marked on each bar.
  • Settings menu, pictures instead of paragraphs: the picture rows show the chain from the 3D scene through the upscaler and the game picture to the window, with your values; the controller rows show your controller live, every button and both sticks over their dead zones; the keyboard and mouse rows show a keyboard with the button each bound key presses; the overlay row shows frame times, the CPU and GPU time per frame and memory; the graphics card row shows the card, driver, memory, processor, display and the device profile the game chose, and why.
  • A problem report in one press: Esc, Advanced, Make a problem report (or Problem report in the launcher) writes one zip with the logs of the last five runs, your settings and the computer's details, and opens its folder. No saves, no game files, your user name taken out of every path; nothing is sent anywhere. When the game stops with an error it says so, and the next start and the launcher point to the report.
  • Video memory: the game now leaves room on the graphics card for a browser and the other programs you have open, and uses about 1.5 GB less of it in play.
  • The setup prepares the game's textures for your graphics card (the launcher's "Prepare textures" row can skip it), so a place seen for the first time does not stutter while its textures are converted. Textures without transparency are now kept at half the size.
  • The frame rate panel (F10) counts frames where they reach the screen, so its average and its lows are what you see.
  • Controllers: with several connected, the one you press is the one the game reads. A pad that is found but whose buttons do nothing (some 8BitDo pads, an Xbox One S pad over Bluetooth) can be read through the system's XInput / DirectInput (Controls, Controller driver: Compatibility).
  • Keyboard and mouse can be switched off while a controller is connected (Controls tab, off by default).
  • A screenshot key of its own: F12 (or F5, F6, F7, F9, or none) saves a PNG into the screenshots folder beside the game, without the menu and the overlays unless you ask for them.
  • The mouse pointer hides after 3 seconds without moving over the game window (1, 5, 10 seconds or never).
  • Mute in the background (Sound tab, off by default).
  • Frame limit: "No limit (240 FPS)" beside 30, 40, 45, 60, 90, 120, 144 and the monitor's rate.
  • The game's exe carries its name and version, for overlays and capture tools that file games by it.
  • A new install starts in base mode on every graphics card (the game's sharp picture without temporal upscaling); DLSS and frame generation are in the game's menu. An existing install keeps its settings.

Fixed

  • The stall a few seconds after every loading screen is gone.
  • Stutter while the hero turns around or runs: the game re-places its render targets every frame while the view turns, and the frame waited inside the graphics driver for each of them. Measured in a village on a 12 GB card: 1-2 frames over 25 ms a minute instead of 4-13, and far fewer visible frame-time jumps.
  • Walking no longer costs frame time: while the hero moves, the game re-sizes its shadow targets every frame, which moved every other render target with them; they keep their storage now.
  • Fewer long frames when you walk into a busy place: the textures the game streams in are made on background threads before the frame needs them. Measured walking into a town square on a 12 GB card: 41-54 frames over 25 ms in the first minute instead of 118-128.
  • The game's own code runs faster: the recompiled code finds the targets of its indirect calls where they are made and stores less before each call, and the game's threads wake each other with less waiting. Measured in a town square: the game's update is 8 percent shorter and the frame rate 5 percent higher.
  • Loading a save is about a second shorter, and the loading picture no longer waits for the game's own unpacking.
  • The game's own edge smoothing at the end of each frame did nothing; it works now (smoother edges in base mode).
  • The start of play after the title: the first seconds no longer read every texture file on the frame's thread.
  • The frame rate fell sharply after many map changes in one session (video memory held after eviction pushed the game past the card's budget). Measured on a 12 GB card: castle grounds after 22 map changes 97 fps instead of 23.
  • Grass, bushes and tree tops could be missing for seconds the first time a place was visited, while their pipelines were built: the pipelines of these draws are now built before play, and a combination met for the first time is drawn at once with a ready stand-in while its own pipeline is built (NVIDIA cards and AMD cards on Windows).
  • The graphics device could be lost after a map change (a pool's memory was read after the game had freed it): a freed pool's memory now waits until no frame in flight can name it.
  • The game's own "new version" notice never appeared (it asked a repository that is not public); it reads the site's release feed now, and switching the check on in the menu checks at once.
  • A new install on a Steam Deck got the monitor's rate as its frame limit instead of the Deck's 40.
  • In the menu, the arrow keys and Delete did nothing on a row just clicked with the mouse.

Known issues

  • A rare GPU crash (device lost) whose cause is not found. If it happens, the game stops with an error, and a crash dump file is now left beside the log for the problem report: please attach the report.
  • In the first dungeon's entrance room, in base mode without DLSS, a light shaft flickers.
  • The first seconds after a loading screen run slower while the new place's textures arrive, and in play single frames can still take 25-50 ms when the game brings in or moves textures (the open field, the graveyard, the lake).
  • With other programs holding much of the card's video memory (a video editor, many browser tabs), the game gets less than it wants and the long frames come back: a 12 GB card with 4-5 GB taken behaves like an 8 GB card.
  • Bushes on the path down from the castle were reported to flicker when the camera turns back toward the town; we could not reproduce it yet.
  • Other programs' sound may stutter for a moment when the game starts.
  • Boss fights were not tested (every dungeon map was).
  • Shaders: the setup prepares every program in the game's files and every combination and pipeline our test runs met (a pass through 67 of the game's 79 maps, under a minute each from one start position). A combination no run met is built the first time it appears: for most kinds a few milliseconds; grass and foliage are drawn with a stand-in meanwhile (on other cards than NVIDIA's and AMD's that patch is not drawn for up to a second). It is kept and never built again.
  • PCs with 16 GB of memory: the game uses about 16-17 GB of the computer's memory in play and commits 24-27 GB, so with 16 GB it pages to the disk, with stutter, and the system's page file must be large enough; 32 GB is recommended. Not run on a 16 GB PC. There the game also does not read the prepared textures ahead at its start, so a first visit after a restart of the PC reads them from the disk while it plays.
  • Windows only: 1.2.0 has no Linux release. A native Linux build exists in development but has not run on a real graphics card yet.
  • With the texture step skipped in the setup, the first visit of each place stutters while its textures are converted.
  • AMD GPUs have been run on one integrated Radeon only; Intel GPUs, a Steam Deck and a ROG Ally have not been run. Under Proton (Steam Deck) the game keeps its own copy of the game's memory for the graphics card, which costs a lot of processor time and memory: do not expect it to be smooth there yet.
  • Cards with 8 GB of video memory have not been measured in long sessions (many map changes in one run).
  • With frame generation on, the water's reflection (by the castle's drawbridge, by day) may flicker in the generated frames. Frame generation off avoids it.
